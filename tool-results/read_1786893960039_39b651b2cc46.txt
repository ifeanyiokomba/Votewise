    30→## API Contract Reference (for frontend agents)
    31→
    32→All routes return `{ success: true, data }` or `{ success: false, error: { message, code, details? } }`. Client helper: `apiFetch<T>(url, init)` from `@/lib/api-fetch`.
    33→
    34→Auth:
    35→- `POST /api/auth/register` body `{name,email,password,organizationName}` → `{user,organization}`. Sets session cookie.
    36→- `POST /api/auth/login` `{email,password}` → `{user}`.
    37→- `POST /api/auth/logout`.
    38→- `GET /api/auth/me` → `{user, organization}` or `{user:null}`.
    39→- `POST /api/auth/forgot-password` `{email}` → `{requested:true}`.
    40→- `POST /api/auth/reset-password` `{token,password,confirmPassword}` → `{reset:true}`.
    41→
    42→Elections (org admin only):
    43→- `GET /api/elections` → `{elections:[{...,_count:{voters,positions,candidates}}]}`.
    44→- `POST /api/elections` `{name,description?,type,startTime?,endTime?,timezone?}` → `{election}` (or `{limitExceeded:true,message}` if plan full).
    45→- `GET/PATCH /api/elections/[id]`.
    46→- `POST /api/elections/[id]/status` `{status}` → `{election}` (or `{activationRequired:true,message}` when going LIVE unpaid).
    47→- `GET/POST /api/elections/[id]/positions` `{title,description?,maxChoices?,order?}`.
    48→- `PATCH/DELETE /api/elections/[id]/positions/[positionId]`.
    49→- `GET/POST /api/elections/[id]/candidates` `{name,photo?,bio?,manifesto?,positionId}`.
    50→- `PATCH/DELETE /api/elections/[id]/candidates/[candidateId]`.
    51→- `GET /api/elections/[id]/voters?search=` → `{voters}`. `POST` `{id,eligible}` toggle.
    52→- `POST /api/elections/[id]/voters/import` multipart `file` + `mode`(preview|import) → preview stats or import summary.
    53→- `GET /api/elections/[id]/results` → `{results,visible}` (full ElectionResults object).
    54→- `POST /api/elections/[id]/results/publish` → `{election}`.
    55→- `GET /api/elections/[id]/analytics` → `{stats,timeline,results}`.
    56→- `GET /api/elections/[id]/audit` → `{logs}`.
    57→- `GET /api/elections/[id]/activation` → `{activation}`. `POST .../activation/pay` → `{payment}`. `POST .../activation/negotiate` `{contactName,contactEmail,contactPhone?,message?,proposedAmount?}`.
    58→
    59→Voter (public, no session):
    60→- `POST /api/voter/verify` `{electionId, voterId, channel?, code?}`:
    61→  - if no code → sends OTP, returns `{sent, attemptsRemaining, voterId, channel, devCode}` (devCode only in non-prod, show it in a dev hint box).
    62→  - if code → `{verified, error?, voterId}`.
    63→  - returns `{alreadyVoted:true}` if already voted.
    64→- `POST /api/voter/vote` `{voterId,electionId}` → `{session, ballot:{electionName,positions:[{id,title,description,maxChoices,candidates:[{id,name,photo,bio,manifesto}]}]}}` or `{alreadyVoted:true}`.
    65→- `POST /api/voter/vote/cast` `{voterId,electionId,sessionId,votes:[{positionId,candidateId}]}` → `{receipt,count}`.
    66→- `POST /api/voter/ballot-status` `{voterId,electionId}` → `{hasVoted}`.
    67→- `POST /api/voter/receipt` `{reference}` → `{verified,reference,timestamp}`.
    68→
    69→Public:
    70→- `GET /api/public/results/[id]` → if published `{published:true, election, results}`, else `{published:false,status,electionName,electionId}`.
    71→- `POST /api/public/verify-ballot` `{reference}` → `{verified,reference,timestamp}`.
    72→
    73→Admin (org admin):
    74→- `GET /api/admin/stats` → `{stats,orgStats,recentEvents,recentAudit,elections}`.
    75→- `GET /api/admin/security` → `{events}`. `PATCH` `{id}` resolve.
    76→- `GET /api/admin/users` → `{users}`. `PATCH /api/admin/users/[id]` `{role?,isActive?}`.
    77→- `GET /api/admin/subscription` → `{subscription}`. `POST .../upgrade {tier}`. `POST .../cancel`.
    78→
    79→Platform admin:
    80→- `GET /api/admin/negotiations` → `{negotiations}`. `PATCH /api/admin/negotiations/[id]` `{status,negotiatedAmount?,internalNotes?,assignedToId?}`.
    81→
    82→Support (org member):
    83→- `GET/POST /api/support` `{subject,description,priority}`.
    84→- `GET/PATCH /api/support/[id]` (PATCH `{status?,assignedToId?}`).
    85→- `GET/POST /api/support/[id]/messages` `{body,isInternal?}`.
    86→
    87→Notifications:
    88→- `GET /api/notifications` → `{notifications}`. `POST /api/notifications/[id]/read`.

  1140→### 1. Hydration Error (CRITICAL — was blocking the landing page)
  1141→- **Root cause**: In `src/app/page.tsx`, the `FinalCta` component rendered `<Logo>` (which outputs a `<div>`) inside a `<p>` tag. HTML spec forbids `<div>` as a descendant of `<p>`, causing a React hydration error.
  1142→- **Fix**: Changed the wrapping `<p>` to a `<div>` and wrapped the text content in a `<span>`.
  1143→- **Verified**: Landing page loads with zero hydration errors.
  1144→
  1145→### 2. Dashboard Routing Race Condition (CRITICAL — dashboard not opening after login)
  1146→- **Root cause**: The login page used `router.push("/dashboard")` followed immediately by `router.refresh()`. This client-side navigation could race with session cookie propagation — the dashboard layout's `useEffect` would fire `/api/auth/me` before the browser sent the new httpOnly cookie, causing the auth check to fail and redirect back to `/login`.
  1147→- **Fix**: Replaced `router.push` + `router.refresh()` with `window.location.href = target` — a hard browser navigation that guarantees the cookie is sent with the next request. Also updated the API response type to include `organizationId` for future role-based redirect logic.
  1148→- **Verified**: Both org-owner and platform-admin logins now reliably reach `/dashboard` with correct rendering.

  1396→## Systematic Audit Process
  1397→
  1398→### Step 1: Reproduce the Issue
  1399→- Tested login with `agent-browser fill` (simulating manual input) → **FAILED** — stayed on `/login`, no error shown
  1400→- Tested login with `agent-browser type` (real keystrokes) → **FAILED** — same result
  1401→- Tested login with "Quick fill" button → **WORKED** — redirected to `/dashboard`
  1402→
  1403→### Step 2: Trace the Full Auth Pipeline
  1404→```
  1405→User types email → Input onChange → RHF updates state?
  1406→User types password → Input onChange → RHF updates state?
  1407→User clicks "Sign in" → form.handleSubmit() called → validates state → if valid: onSubmit()
  1408→onSubmit() → fetch /api/auth/login → API returns 200 → window.location.href = "/dashboard"
  1409→```
  1410→
  1411→### Step 3: Identify the Breakpoint
  1412→- Installed a fetch interceptor in the browser to trace API calls
  1413→- **Result**: The fetch to `/api/auth/login` was NEVER called when using manual input
  1414→- This means `form.handleSubmit()` was called but `onSubmit()` was never invoked
  1415→- `handleSubmit()` only skips `onSubmit` when **validation fails**
  1416→
  1417→### Step 4: Root Cause Diagnosis
  1418→- Tested the Zod schema directly → validation passes with correct values
  1419→- Tested the `zodResolver` directly → returns correct values with no errors
  1420→- Checked React version → React 19.2.3 (new event delegation system)
  1421→- Checked RHF version → react-hook-form 7.71.1
  1422→
  1423→**ROOT CAUSE**: React Hook Form's internal state was NOT being updated when the user typed in the input fields. The `onChange` events from React 19's synthetic event system were not properly triggering RHF's state updates. When `handleSubmit()` was called, it validated against the **default empty values** (`{ email: "", password: "" }`), which failed validation silently (no visible error because the form fields were visually populated).
  1424→
  1425→The "Quick fill" button worked because it used `form.setValue()` which bypasses the event system and directly sets RHF's internal state, then calls `form.handleSubmit(onSubmit)()`.
  1426→
  1427→### Step 5: Solution Implementation
  1428→
  1429→**Approach**: Completely rewrite the login and register forms without React Hook Form, using plain `useState` for form state management. This is bulletproof because:
  1430→1. `useState` + `onChange` is the most fundamental React pattern — no compatibility issues possible
  1431→2. The form values are always in sync with the DOM
  1432→3. Validation is done inline with simple `if` statements
  1433→4. No dependency on `zodResolver`, `@hookform/resolvers`, or `react-hook-form`
  1434→
  1435→**Login page changes**:
  1436→- Replaced `useForm` + `FormField` + `FormControl` with plain `<Input value={email} onChange={...} />`
  1437→- Replaced zod schema validation with inline checks (`if (!email.includes("@"))`)
  1438→- Added error query param handling for Google auth redirect errors
  1439→- Updated `quickFill` to set state directly and use `form.requestSubmit()`
  1440→
  1441→**Register page changes**:
  1442→- Same approach — replaced all RHF components with plain `useState`
  1443→- Kept the institution type dropdown, password strength meter, and Google auth button
  1444→- Inline validation for all fields
